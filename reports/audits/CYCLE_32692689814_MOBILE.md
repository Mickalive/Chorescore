La seconde moitié du commentaire (comparaison `assertive` vs `polite` avec le chrono de `TaskRow`) est exacte ; l'attribution du motif de remontage ne l'est pas. Risque : précédent fabriqué qui fausse la traçabilité des décisions, contraire à la discipline d'honnêteté du dépôt.

- **Correction minimale** : reformuler les deux commentaires pour décrire le mécanisme pour lui-même (jeton → `key` fraîche → re-annonce Android) et ne conserver que la comparaison exacte des niveaux `assertive`/`polite` avec `TaskRow`.
- **Vérification** : plus aucune référence à « motif TaskRow » comme source du remontage ; relecture des commentaires.

### F2 — Handler `onShow` sans garde de visibilité pour la fermeture pendant l'ouverture (faible)

- **Gravité** : faible.
- **Chemin/symbole** : `src/components/ManualEntryModal.tsx` (`onShow={() => minutesInputRef.current?.focus()}`) et `src/components/TaskFormModal.tsx` (même motif).
- **Scénario** : l'utilisateur ouvre une modale puis la referme pendant l'animation d'ouverture. Sur certaines plateformes/versions de React Native, un `onShow` tardif peut encore se déclencher après que `visible`/`task` est repassé à faux ; le handler focus alors un `TextInput` toujours monté dans l'arbre React mais invisible, ce peut faire surgir le clavier au-dessus de l'écran sous-jacent (« focus volé »). L'ancien code couvrait exactement cette course via `clearTimeout` dans le cleanup ; la protection a disparu avec le timer. Cas limite non prouvé sur les versions actuelles, conséquence transitoire et récupérable.
- **Preuve** : diff supprimant `const timer = setTimeout(...); return () => clearTimeout(timer);` sans replacement ; handlers `onShow` sans test de visibilité ; effet de remise à zéro `[task]`/`[visible]` distinct du moment où `onShow` peut fire.
- **Correction minimale** : garder un ref miroir de la visibilité courante (ou lire `task !== null` / `visible` via ref) et ne focus dans `onShow` que si la modale est encore ouverte.
- **Vérification** : test de condition de données ou inspection montrant qu'aucun focus n'est demandé quand la modale est fermée au moment de `onShow`.
