## Constats

### F1 — [repair] `src/store/persistence.ts` — validation `householdLimit` casse la migration legacy

- **Problème:** `isHousehold` exige `householdLimit === null || integer` et `maxMembers === null || integer`. Les documents v2 acceptés (avant ce cycle) n'ont pas la clé `householdLimit`; ils sont désormais jugés `invalid-shape` et mis en quarantaine (`recovered/quarantined:true`) au lieu d'être migrés transparentement. Contraire à TASKS acceptance « données anciennes migrées/récupérées sans perte silencieuse » (DRC-02 complete à préserver).
- **Preuve:** Diff `src/store/persistence.ts` : ajout `hasValidLimit` testant `value.householdLimit`. Ancien validateur : seul `maxMembers`. Reproduction : `const durable = makeDurable(); delete (durable.households[0] as any).householdLimit; isDurableState(durable) === false; parseEnvelope(JSON.stringify({schemaVersion:2,savedAt,state:durable})) => {outcome:'invalid', reason:'invalid-shape'}` ; `loadDurableState` seeded avec cet ancien JSON → `{status:'recovered', reason:'invalid-shape', quarantined:true}`. Tests verts masquent car `createDemoSnapshot` injecte désormais `householdLimit: null`.
- **Correction requise:** Rendre `householdLimit` optionnel : `isHousehold` doit accepter `undefined` comme `null` (`value.householdLimit === undefined || value.householdLimit === null || integer`). À la lecture, normaliser `undefined` → `null` (ou `maxMembers`) dans `parseEnvelope`/`isDurableState` ou via migration v2→v2 silencieuse sans bump version. Ajouter test non-régression : ancien JSON sans `householdLimit` doit restaurer `restored` avec `householdLimit === null`.
- **Vérification:** Construire un `DurableState` de l'arbre accepté sans `householdLimit`, appeler `parseEnvelope`/`isDurableState` depuis `src/store/persistence.ts` corrigé : attendu `outcome:'valid'`. `loadDurableState` via `MemoryStorage` doit rendre `restored` sans quarantaine et `households[0].householdLimit === null`. `npm run check` doit rester vert.
