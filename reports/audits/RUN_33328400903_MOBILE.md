## Findings

### F1 — `app/(tabs)/index.tsx` — mustFix: true
**Problem:** Le champ `Fait par` n'est pas modifiable : l'UI affiche statiquement le performer courant au lieu de permettre le choix de n'importe quel membre du foyer, contrairement à l'acceptance DRC-01 tranche 2 et MAIN_PROMPT §3.

**Evidence:** `app/(tabs)/index.tsx` L214-216 `const performer = householdMembers.find(m=>m.id===state.currentUserId) ?? householdMembers[0];` L353-356 `<Text>Fait par</Text><View><Text>{performer?.name ?? '—'}</Text></View>` — aucun Pressable/SegmentedControl/chips pour performer. `handleSubmit` L273 `performedByMemberId: performer.id` fixe. `grep performer` → 0 sélecteur. Comparé à `Fait pour` qui a `MemberChip` + `toggleEveryone`/`toggleBeneficiary` (L220-240). Tests `drc01` AC5 exigent `validatePerformedBy` et capacité à choisir autre membre.

**RequiredFix:** Rendre `Fait par` modifiable : exposer un sélecteur listant `householdMembers`, défaut = `currentUserId`, valeur stockée dans state `performedByMemberId`, utilisée dans `handleSubmit` et validée par `planAddCompletedEntry` (déjà prêt). Réinitialiser après succès.

**Verification:** Ouvrir `Ajouter une tâche` en démo : `Fait par` propose tous les membres, défaut = utilisateur connecté, changement → `CompletedEntry` créée avec `performedByMemberId` correspondant (vérifier via `selectVisibleEntries` et reload persistence V3). `npm run check` reste vert.

### F2 — `app/(tabs)/index.tsx` — mustFix: false
**Problem:** Unité de durée ambiguë et bornes manquantes : champ manuel placeholder `secondes` + `parseFloat` sans validation 1..1440 min ni message inline, alors que le domaine attend `durationSeconds` avec contrainte métier.

**Evidence:** L387-394 `<TextInput placeholder="secondes" keyboardType="numeric" value={manualSeconds}>` ; L262-268 `parsed=parseFloat(manualSeconds); if (!finite||<=0) alert(...)` — aucune borne haute, aucun contrôle d'entier, aucun usage de `validateManualMinutes`. `chrono.stop()` retourne secondes, cohérent mais UI ne précise pas (spec : 1 min réelle = 1 min).

**RequiredFix:** Clarifier l'unité et brancher validation existante : afficher aide + validation >0 et <=86400 avec entier, erreur inline comme `labelError`. Si minutes souhaitées, convertir ×60.

**Verification:** Saisir 0, -1, 0.5, 1500, texte → erreurs inline ; saisir 60 → `durationSeconds` correct ; chrono → duration >=1s. Vérifier via `planAddCompletedEntry`.

### F3 — `app/(tabs)/score.tsx` — mustFix: false
**Problem:** Onglet `Score` placeholder sans statistiques/équilibres Tricount ni historique filtré : conforme à l'acceptance minimale tranche 2 mais ne couvre pas encore MAIN_PROMPT §5 et DRC-03.

**Evidence:** `score.tsx` : `ScreenHeader` + `NoticeBanner` + placeholder `Score — bientôt` sans `calculateBalances`/`calculateCompensations`, sans filtres `Toutes/PersistentTask/Autres`, sans périodes, sans graphe. TASKS acceptance : “Les screens Ajouter une tâche, Score et To-do sont accessibles en demo sans réseau.”

**RequiredFix:** Tranche DRC-03 : périodes semaine/mois/année/depuis le début, filtres, calcul fait-par/fait-pour à somme nulle, compensations, temps réel + graphe noms/valeurs, pondéré secondaire, historique contextuel et partage.

**Verification:** Changer période/filtre → soldes recalculés, graphe noms+heures, historique filtré cohérent, partage ouvre share sheet.

### F4 — `app/(tabs)/todo.tsx` — mustFix: false
**Problem:** Onglet `To-do` placeholder sans création/assignation ni conversion : conforme tranche 2 mais ne couvre pas §6 et DRC-04.

**Evidence:** `todo.tsx` même pattern placeholder, aucun form `TodoItem`, `AppState` `todoItems` existe et reducer gère `ADD_TODO`/`COMPLETE_TODO` mais aucune UI ne l'alimente.

**RequiredFix:** DRC-04 : To-do datée ou non, assignée, fait pour, note, deadline/reminder, check ouvrant mini-formulaire `Fait par/durée/fait pour` créant atomiquement `CompletedEntry`.

**Verification:** Créer Todo, cocher → modale → CompletedEntry créée, Todo `completedAt` rempli, historique et Score mis à jour, persistence V3 reload OK.
